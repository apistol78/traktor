One Token Through Llm

An inference engine is a loop that turns one integer into a probability distribution over the next integer. Everything else — the file format, the tokenizer, the cache, the sampler — exists to feed that loop or to make it cheap. This walks the whole path through tools/Llm, one stage at a time, with the source beside it.

§ 1

The whole engine in one picture

Who owns what, and what moves between them

Three objects hold state and the rest are pure functions over it. Model is the file: weights, vocabulary, chat markup, immutable once loaded. Context is one conversation: the key/value cache and the scratch buffers of a single forward pass. Generator is the loop, running on a thread of its own so the UI never blocks.

A reply is produced by pushing the whole conversation through the network one token at a time to fill the cache, then generating tokens until the model emits an end-of-turn marker. Nothing is batched — the prompt costs one full forward pass per token, which is the engine's largest deliberate simplification.

The classes

Read it in this order. GgmlType → Quant → GgufFile gets you the file. Ops → Context is the network, and is the only part where the maths lives. Everything else is text handling around the edges.
§ 2

The file is a header and a wall of bytes

GgufFile · GgmlType · Quant

A GGUF file is a small key/value header, a directory of tensors, and then every weight in the model packed end to end. GgufFile::create maps the file and parses only the header GgufFile.cpp:303; the payload is never copied, never decoded up front, and never resident beyond what the page cache decides to keep.

That single decision shapes the rest of the engine. Weights stay in their stored, quantized form, and every matrix product decodes them on the fly. A 2 GB model opens instantly and the process never allocates 2 GB.

A weight is a block, not a number

Quantized formats do not store one scale per tensor or one per row — they store one per small block of elements. That is the whole trick: a block of 32 four-bit quants plus a 16-bit scale costs 4.5 bits per weight and still tracks local dynamic range. The K-quants go further and nest sub-blocks inside a 256-element super block, with the sub-block scales themselves quantized to six bits.

Decoding without materializing

dotRow is where the design pays off. A row of a quantized matrix is never expanded into a float array — it is decoded one 256-element window at a time into a stack buffer, dotted against the input, and discarded Quant.cpp:239–271. No allocation, no second copy of the model, and the window stays in L1.

A token therefore streams essentially the entire model through the CPU once. That is why inference here is memory-bound, and why the quantization format — not the FLOPs — sets the speed.
§ 3

Text becomes integers, in three stages

ChatTemplate · Vocabulary · Tokenizer

The network never sees text. It sees a list of vocabulary indices, and the model was trained to expect those indices arranged in a very specific ritual of role markers. Getting that ritual wrong does not crash anything — it just makes the model answer a question nobody asked.

1 · The conversation is wrapped in markup

GGUF carries the real chat template as a Jinja program. Interpreting Jinja is far more than this engine needs, so ChatTemplate::create recognises the family from the markers the template mentions and uses a hand-written formatter for it ChatTemplate.cpp:42–74. Recognition is by marker, not by model name, because redistributed files lie about their names.

switcher

ChatTemplate::format

ChatTemplate.cpp:96–193

Note the tail of every rendered prompt: it ends opening the assistant's turn. The model is not asked to reply — it is put in a position where the only sensible continuation is a reply. Detecting the end of that reply is Vocabulary::isEndOfGeneration, which collects the end-of-sequence id plus every end-of-turn marker it can find, because on chat-tuned models those are usually different ids Vocabulary.cpp:130–147.

2 · Markup is lifted out before merging

If <|im_start|> went through the normal merge loop it would come out as four or five ordinary tokens, and the model would see something it has never been trained on. So Tokenizer::encode scans for control and user-defined tokens first, emits each as its single id, and runs the regular tokenizer only on the spans in between Tokenizer.cpp:530–566. The special list is sorted longest-first at load so a short marker can never shadow a longer one Vocabulary.cpp:94–98.

The same function takes parseSpecial as a parameter for a reason: prompts built from a template want markup recognised, arbitrary user text must not be able to inject it.

3 · The merge loop

Both tokenizer families are the same algorithm with a different priority. Text is cut into symbols, every adjacent pair that exists in the vocabulary is pushed onto a priority queue, and the best pair is merged repeatedly — each merge creating up to two new candidate pairs with its new neighbours. mergeSymbols is shared by both Tokenizer.cpp:447–469; only what goes on the queue differs:

  • SentencePiece pushes the merged token's score, highest first Tokenizer.cpp:668. Symbols are whole UTF-8 characters, and a space is written ▁.
  • Byte-pair pushes the negated merge rank, so the lowest rank wins Tokenizer.cpp:719. Symbols are single bytes, mapped to printable code points first, and text is cut by a pre-tokenizer pattern before any merging.

The symbols are a doubly linked list inside a vector, and merged-away entries are left in place with n == 0 rather than removed; the queue is allowed to hold stale candidates and they are checked on pop Tokenizer.cpp:458–460. Step through it:

Anything that survives with no vocabulary entry falls back to one token per byte — <0xNN> for SentencePiece, the byte-level code point for BPE Tokenizer.cpp:743–764. That is why a model can echo a character it has never seen: it spells it.

§ 4

One token through the network

Context::evaluate · Ops

This is the engine. Context::evaluate(token, computeLogits) takes one integer, walks it through every layer, and leaves a vocabulary-sized row of logits behind Context.cpp:116–184. Sixty-nine lines. Everything else in the module exists to make these sixty-eight lines possible.

The shape of it: a single vector — the residual stream m_x, embeddingLength floats wide — starts as the token's embedding row and is modified in place by every layer. Each layer adds two things to it: an attention result and a feed-forward result. Nothing else is carried between layers.

The five operations underneath

		

			
Ops.cpp is 166 lines and contains every kernel the network needs. Nothing is fused, nothing is blocked, nothing is AVX2.

		


		

			

				
matmul Ops.cpp:66

				
One output per row of the weight matrix, each a dotRow against the input. Rows are split across the job manager by parallelFor; this is the only place parallelism exists, apart from attention.

				
rmsNorm Ops.cpp:78

				
Scale by the root mean square, then multiply by a learned per-channel weight. No mean subtraction, no bias. The sum of squares accumulates in double — at 4096 channels a float accumulator loses enough precision to visibly move the activations.

				
softmax Ops.cpp:92

				
Shift by the maximum before exponentiating, or the largest score overflows. Used twice: on attention scores, and on the logits inside the sampler.

			

			

				
siluMultiply Ops.cpp:113

				
SwiGLU in one line: x = x / (1 + exp(-x)) * y. The gate branch is squashed by SiLU and used to modulate the up branch. This is why the feed-forward block needs three matrices instead of two.

				
rope Ops.cpp:132

				
Rotate pairs of channels by an angle proportional to the position. This is the only place a position enters the network Context.cpp:154 — remove it and the model becomes a bag of words.

				
parallelFor Ops.cpp:33

				
One task per worker plus one, capped at 32, skipped entirely below 16K units of work. JobManager::fork runs one task on the calling thread — which is exactly why generation may not run on a job worker.

			

		


		
Rotary position, in detail

		

			
Each head's channels are paired up, and each pair is rotated by θ = position × freqScale / freqBase^(2i/ropeDim). Low pairs rotate fast — they encode "a few tokens ago"; high pairs rotate slowly and encode long-range order. Because the rotation is applied to both query and key, the dot product between them depends only on the difference of their positions, which is the whole point.

			
Two things vary by model. The pairing: RopeType::Normal rotates channels (2i, 2i+1), RopeType::NeoX rotates (i, i + ropeDim/2) — picked from the architecture name, since a wrong choice still reads fluently and merely stops tracking word order Model.cpp:39–43. The stretching: a linear freqScale, or the per-pair divisors Llama 3.1 ships in rope_freqs.weight, which stretch only the slow channels and leave the fast ones alone Model.cpp:289–302.

Attention, and why the cache exists

		

			
Context::attend runs one job per query head Context.cpp:196–242. For head h it scores the current query against every key already in the cache, softmaxes those scores, and sums the values with those weights. There is no explicit causal mask: positions after the current one simply are not in the cache yet, so length = position + 1 is the mask.

			
Query heads outnumber key/value heads on every modern model — grouped-query attention. Several query heads share one cached head, kvHead = h / groupSize, which is what makes the cache affordable: a model with 16 query heads and 2 key/value heads stores one eighth of the cache it otherwise would.

The cache is the memory, and the bill

Attention at position n needs the keys and values of every earlier position. Recomputing them would make generation quadratic, so they are written once, at the position that produced them, and read for the rest of the conversation. Layer-major, then position, then channel Context.cpp:141–142:

Reusing the prefix

		

			
Every turn re-renders the whole conversation through the chat template, so the token list for turn 4 begins with the exact token list of turn 3. Generator::generate walks the two lists together, finds how far they agree, rewinds the cache to that point and evaluates only the tail Generator.cpp:244–252. Context::rewind is a cursor move; nothing is cleared, because nothing past the cursor is ever read Context.cpp:105–114.

			
Without this, a ten-turn conversation would re-read every earlier turn on every reply. With it, the cost of a turn is the new text plus the reply.

§ 6

			
Choosing the next token

			
Sampler

		


		

			
The forward pass ends with one raw score per vocabulary entry. It is not a probability, it is not normalised, and it is not sorted. Sampler::sample turns that row into exactly one integer Sampler.cpp:43–131, and it modifies the logits in place — the row belongs to Context and is overwritten by the next token anyway.

			
Four stages, in this order, each one narrowing what can be drawn:

			
    
				
  • repetition penalty — recent tokens are pushed down. Positive logits are divided, negative ones multiplied, so the penalty always moves a token down regardless of sign Sampler.cpp:48–64.
    • 
				
  • temperature — divide every logit. Zero or less skips everything below and takes the argmax Sampler.cpp:66–74.
    • 
				
  • top-k — keep the k best. It runs first because it bounds the sort nucleus sampling needs Sampler.cpp:89–101.
    • 
				
  • top-p — keep the shortest prefix holding at least p of the probability mass Sampler.cpp:104–115.
    • 
			

			
What survives is renormalised and drawn from by a linear scan against a uniform random number Sampler.cpp:117–131.

§ 7

			
The loop, the thread, and the half-character problem

			
Generator · Utf8 · ChatForm

		


		

			
Generation runs on a thread Generator creates for itself Generator.cpp:58–67, and that is not only about keeping the UI responsive. The forward pass forks work onto the job manager, and JobManager::fork runs one of the tasks on the calling thread — so evaluation must never itself be running on a job worker Ops.cpp:56–58. A private thread guarantees the separation.

			
Nothing in the engine calls back into a widget. Output accumulates into a string, and ChatForm drains it from a 50 ms UI timer with flushText() ChatForm.cpp:351–366. That is the whole streaming mechanism: no callbacks, no marshalling, no locks held across a repaint.

		


		

		
Half a character is not text yet

		

			
A token carries bytes, not characters. Byte-fallback tokens carry exactly one byte, and a multi-byte character routinely arrives across two or three tokens. Handing those bytes straight to the UI produces a flash of replacement characters at every accent and every emoji.

			
So appendText keeps a m_partial buffer and only releases the prefix that no further byte can change, measured by getValidUtf8Length Generator.cpp:411–426. The rule is precise: a valid lead byte whose sequence is still short is held back; a byte that can never be repaired is released immediately, because waiting for it would stall forever Utf8.cpp:96–100.

§ 8

			
What it costs, and how you would know

			
The honest limits, and the diff that finds a regression

		


		

			
The engine is correct before it is fast, and it says so. Four limits are structural rather than accidental:

			
    
				
  • SSE2 is the widest kernel. dotF32 uses Vector4, and Traktor's math has no AVX2 path and no int8 dot product. An AVX2 kernel is the single biggest win available.
    • 
				
  • No batched prefill. A prompt is consumed one token at a time, one full forward pass each. Only the output projection is skipped — computeLogits is false for every prompt token but the last Generator.cpp:271–275, which is the cheapest speedup available and worth roughly a tenth of the pass.
    • 
				
  • The context defaults to 4096, not to what the model was trained for, so long conversations are truncated from the front sooner than the model could manage.
    • 
				
  • YaRN and LongRoPE are detected, not implemented. Running them unscaled is wrong; quietly substituting a linear factor would be worse, so the engine warns and leaves positions alone Model.cpp:236–243.
    • 
			

		


		

			The logits line is the regression test. -selftest prints the hyperparameters, every tensor's shape and first decoded weights, a tokenizer round trip, a summary of the logits after the prompt, and a short greedy generation SelfTest.cpp:189. The logits summary moves on any change in the forward pass, including differences far too small to change which token is sampled. A greedy argmax is not a sensitive test; the logits are.
